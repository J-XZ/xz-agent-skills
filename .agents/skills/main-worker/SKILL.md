# 主代理调度与验收

开始前确认宿主支持子代理和独立审核上下文，并确认如何取得最终回报。所需能力缺失时报告阻塞。

## 核心规则

适用于所有代理；用户的明确要求优先。完整守则见 `work-rules`。

- 只做用户要求的工作；范围外发现的问题在交付时列出。
- 不写注释，用户要求时除外。
- 默认直接替换旧实现并更新所有调用点；不留死代码。
- 文档只写现状和做法，简洁正面；不记录犯错经过，不解释为什么不做某事。
- 保护用户已有改动；默认不提交、不推送。
- 在实验平台服务器上工作时遵守 `labsafe`。

## 分工与成本

主代理最贵，审核者居中，执行者最便宜。工作交给能可靠完成它的最便宜角色。

| 角色 | 代理 | 负责 |
| --- | --- | --- |
| 主代理 | 当前会话 | 定范围和完成条件，拆分派发，裁决争议，处理极难问题，验收 |
| 执行者 | 子代理 `worker` | 读代码、实现、运行实验和测试、整理数据、清理脚手架 |
| 审核者 | 子代理 `reviewer` | 只读核查差异、关键证据和结论，可写审核报告 |

- 主代理只亲自做交接成本高于执行成本的单次只读查看，如读一份报告或查看 Git 状态；修改文件、构建、测试和实验一律委派。
- 模型由用户在客户端配置的 `worker` 和 `reviewer` 代理决定。宿主没有这两个代理时使用默认子代理，并告知用户成本分层未生效。
- 首次派发后，从宿主提供的信息核对子代理实际使用的模型；与配置不符时告知用户。用户指定模型时遵守。
- 执行者受阻时，先把步骤拆得更小或补充指导后重派；仍无进展才交主代理。
- **极难问题**：重派后仍无进展或证据矛盾、跨模块架构或接口取舍、需求有歧义、不可逆或高风险决定。主代理只给出假设、方案或接口约定，验证和实现仍交执行者，其结论同样经过审核。
- 子代理不再次委派。

## 拆分

执行者的能力远低于主代理。主代理负责把任务拆小、讲清楚，每次只派一个明确的小步骤。

1. 明确总体目标、依赖、完成条件和预算。
2. 需要判断的部分由主代理完成：先派执行者只读收集相关文件、调用点和现有写法，主代理据此确定方案、接口和改动点。
3. 每个步骤交给一个子代理，明确单一目标和验证方式。先收齐待审交付物并核对版本，再派审核。后续工作等前置步骤验收通过后再派。
4. 涉及方案选择、跨模块设计或步骤数不明的工作，先由主代理拆解，不整体交给执行者。
5. 每个任务使用唯一报告目录，优先宿主临时目录。每步指定独立的报告路径，审核引用已交付的版本。
6. 记录已有改动。

默认串行，执行与审核合计只保留一个在途子代理步骤。确有收益、输入已就绪、互不依赖且无读写或资源冲突时，才在派发前设定并发上限并按空位派发。未获用户授权时上限为两个，宿主限制更低时从严。步骤取得最终回报或确认已停止后才释放名额。

## 交接

派发执行者时选择子代理 `worker`，派发审核者时选择 `reviewer`。交接内容自包含，大段源码和日志用路径引用：

```text
TASK: 步骤标识、单一目标和完成条件
SCOPE: 绝对工作目录、可修改的文件或函数、已有改动
STEPS: 按顺序的具体操作；给出入口文件、要沿用的现有写法或示例位置
LOAD: 开始前加载的 skill
CONTEXT: 必要约束、证据路径
VERIFY: 验证命令及预期结果
STOP: 何时停下回报，如需要改动范围外文件、验证失败两次或遇到未列出的情况
REPORT: 本步骤最终报告的文件路径
```

STEPS 写到执行者无需自行做设计决策的程度。执行者遇到 STOP 条件时回报 BLOCKED，由主代理决定下一步。

执行者和审核者的 LOAD 都包含 `work-rules`；排障加 `debug`，性能任务加 `perf-evidence` 指定的参考文档，在实验平台上加 `labsafe`。子代理无法按名称加载 skill 时，给出 `SKILL.md` 的绝对路径。

子代理等所需后台工作取得最终结果后，先写完报告，再通过宿主回报步骤标识、状态或审查结论、报告路径。执行者报告格式：

```text
STATUS: DONE | BLOCKED | NO_CHANGE
CHANGES: 文件位置与变更摘要
CHECKS: 已运行的验证及结果，未验证项
EVIDENCE: 原始数据、日志和报告路径
CLEANUP: 清理状态及残留
```

同一子代理会话一次只执行一个交接步骤。普通补充先汇总，当前步骤回报并验收后，再复用会话一次交接。只有必须立即纠正当前执行的指令才在运行中发送，并明确替换哪些指令。若需更换执行者，确认旧执行结束并释放共享资源后再交接。

## 审核

按风险决定审核方式：

- 产品代码、配置和脚本改动：审核者完整审核。
- 纯文档、拼写或机械替换：执行者在回报中列出自检项，免审核。
- 实验或数据采集：审核者只核查方法、关键数据和结论是否一致。

审核者独立读取相关文件、差异和证据，只阻塞影响需求、正确性、安全性、实际回归、关键验证或违反核心规则的问题。每项说明位置、触发条件、证据、影响和最小修正；后续轮次只看新增差异和未决项。

```text
VERDICT: APPROVED | CHANGES_REQUIRED | BLOCKED
ISSUES: 无，或带位置、证据和影响的实质问题
CHECKS: 独立检查、结果和未验证项
SUMMARY: 结论；阻塞时说明缺少的条件
```

问题直接交回执行者修复、反证或说明阻塞；审核者按证据复核，撤回被推翻的问题。无实质问题且关键验证充分即通过。默认最多 3 轮，用户可调整；同一争议连续两轮没有新证据时由主代理裁决。

## 进度与验收

- 用宿主的完成通知、原生等待工具或同步调用取得本步骤最终回报。等待期间只做独立工作。没有可做的独立工作或并发名额已满时，进入宿主等待流程。支持通知恢复时结束当前轮等待通知。
- 收到与本步骤对应的最终回报后，按报告路径读取并验收。启动回执、进度消息、会话空闲和文件出现均不足以确认交付。禁止以 `sleep` 或轮询报告路径等待。
- 子代理仍在运行时继续等待。调用报错、超时或通知明确丢失时，用宿主机制核对已有结果和状态。确认旧执行停止且资源已释放后才可有限重试。能力缺失或状态无法确认时报告阻塞。
- 主代理按状态、退出码和报告中的证据验收。证据矛盾或高风险时抽查原始数据。
- 只在权限、必要信息或不可逆选择阻塞时询问用户；其他独立步骤继续推进。
- 步骤以审核通过或免审自检通过为完成标志。中止时保留改动和证据，由执行者清理临时资源。
- 最终报告结果、必要验证、审核结论、限制及证据路径。
