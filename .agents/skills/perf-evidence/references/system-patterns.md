# 系统性能线索

只查与目标相关的行，表中内容是待验证方向。

从项目文档、依赖、构建文件和 CI 发现测试及观测入口。优先复用性能分析、追踪、慢查询和运行时统计；缺少负载入口时，在任务临时目录编写最小代表性负载。

| 系统 | 常见成本 | 有区分力的证据与对照 |
| --- | --- | --- |
| 数据库与存储引擎 | 扫描、排序、锁、缓存、刷盘、整理、复制 | 扫描与返回行数、磁盘溢出、锁等待、缓存未命中成本；比较相关规模、热点或冷热状态 |
| Web 与 API | 排队、连接池、下游调用、重试、序列化、GC | 客户端与服务端耗时分解、池等待、重试、停顿；固定负载观察饱和及慢下游影响 |
| 文件系统与存储 | 元数据、缓存、I/O、同步写入、复制、压缩 | 分开测元数据与数据路径，观察队列、写放大和锁等待；使用实际文件大小与访问模式 |
| 批处理与数据管道 | 调度、数据交换、序列化、倾斜、重试、检查点 | 阶段耗时、传输字节、分区大小、最慢任务和重试；固定数据做对照 |
| 嵌入式与边缘设备 | 中断、DMA、内存、闪存、热限频、冷启动 | 周期、停顿、频率、温度、I/O 延迟；复现目标资源约束与启动路径 |

- 区分 CPU 时间、墙钟时间和等待时间；嵌套或并行计时分别报告。
- 归因要求组件位于目标指标的关键路径上，利用率或调用数只作线索。
- 选择能区分候选机制的最小对照。
- 优化须保持持久性、一致性、TLS、校验和必要重试等语义。
- 清缓存、停止服务和故障注入须在授权且可恢复的环境中进行。
