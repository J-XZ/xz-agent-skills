# 性能优化实证

流程：明确目标 → 静态假设 → 实验计划 → 实测 → 建议 → 清理。用户已要求实施优化时继续实现和对比；只要求分析或建议时，交付建议即止。

调度、交接和独立审核使用 `main-worker` 指定的 OpenCode 会话。执行者和审核者的操作细则在 [实验手册](references/experiment.md)，交接时在 LOAD 中给出它的路径；主代理无需阅读。

## 分工

| 角色 | 负责 |
| --- | --- |
| 主代理 | 定主指标、代表性负载、环境、正确性约束和预算；按假设拆分实验步骤；裁决矛盾结论和难以归因的问题 |
| 执行者 | 提出假设、写实验计划、运行实验和插桩、整理原始数据、实施优化、清理 |
| 审核者 | 开跑前审实验计划，结束后核查数据、统计量、结论和方案可行性 |

- 实验、基准、插桩和数据整理一律由执行者运行；同一实验环境只派一个执行者。
- 每个实验步骤只验证一个假设，交接时写明预测、对照和判定阈值的要求。
- 实验计划交付后派发审核，审核通过后开跑。实验完成并交付结果后派发结果审核，通过后再交付建议或进入实施。

## 停止

证据充分即停止；默认最多 5 轮实验（含补测），可按用户预算调整。

## 交付

最终说明结论（`CONFIRMED` / `REFUTED` / `INCONCLUSIVE`）、建议、关键数值与波动、验证限制、清理状态和产物路径。正常完成时保留用户已授权的优化，回滚按用户要求处理。
